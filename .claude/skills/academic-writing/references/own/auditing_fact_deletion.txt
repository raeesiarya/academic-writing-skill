010

                     Language models with separable memory aim to decouple source-specific knowl-
012                  edge from general world knowledge, language understanding and reasoning ca-
013                  pabilities. Unlearning then becomes relatively straightforward: simply delete the
014                  memory units associated with the targeted knowledge. We show that a naive com-
015                  parison of model outputs is an unreliable measure of unlearnability, and propose a
016                  methodological audit for such systems that measures the effectiveness of memory
017                  removal. We apply the audit to Continuous-Query Limited Memory Language
018                  Models (Co-LMLM) and Natively Unlearnable Large Language Models (NULLs)
019                  on five factual-recall benchmarks. Much of the post-deletion correctness in both
020
                     systems is also present when separable memory is disabled. This is expected for
                     NULLs by design, but less so for Co-LMLM, which aims to keep facts out of its
021
                     weights. In NULLs, the backbone recites up to 81.1% of audited facts without
022
                     any source memory, and removing more sources does not remove more facts but
023                  damages up to 13% of nearby ones. For Co-LMLM, up to 21.2% of all facts that
024                  pass a naive accuracy test as unlearned are still recited by the backbone. A single
025                  entry re-inserted into Co-LMLM’s memory restores 37.9–83.0% of facts the model
026                  no longer answered after deletion. We propose the audit as a protocol that future
027                  work on separable memory can use to support deletion claims.

      1      I NTRODUCTION
031
032
033
      There are two common reasons to delete a fact from a language model. A person may ask for their
      data to be removed (Fosch-Villaronga et al., 2018), or the training data may contain information that
034
      should not have been included. In either case, the operator must both remove the relevant information
035
      and provide an auditable basis for the deletion claim (Thudi et al., 2022). This is difficult when
036   knowledge is distributed across shared model parameters. A model may stop producing a fact even
037   though information about it remains internally encoded (Lynch et al., 2024), while removing it from
038   the parameters may require retraining or edits whose broader effects are difficult to control (Bourtoule
039   et al., 2021; Meng et al., 2022; Mitchell et al., 2022a; Cohen et al., 2024). Models with separable
040   memory offer a different approach by placing some knowledge in memory units that can be disabled
041   directly.
042   Two such systems, Co-LMLM (Feldman et al., 2026) and NULLs (Ghosal et al., 2026), serve as our
043   case studies. Co-LMLM pairs a language-model backbone with an external memory of text entries.
044   NULLs instead associates each training source with a sparse mask over a shared pool of sink neurons,
045   while information common to many sources can remain in the backbone. In both systems, deletion
046   acts on explicit memory units: external entries in Co-LMLM and source-specific memory in NULLs.
047   The central question is whether disabling the units associated with a requested fact is enough to
048   remove that fact from the system.
049   A standard way to evaluate deletion is to compare the model’s output before and after the intervention
050   (Maini et al., 2024; Shi et al., 2025; Li et al., 2024), including in systems with separable memory
051   (Zhao et al., 2026; Feldman et al., 2026; Ghosal et al., 2026). This comparison does not explain why a
052   fact is still recited after deletion. It may be supported by memory units that were not removed, or the
053   backbone may recite it without separable memory at all. The reverse can also happen: the backbone
      may recite a fact when memory is disabled, while the memory that remains after deletion causes

057   We introduce an audit that separates these cases. For each fact, we evaluate the same prompt with
058
      the full memory available, with the deletion set disabled while the remaining memory stays active,
      and with separable memory disabled entirely. Comparing the latter two conditions tells us whether
059

060
      reveals cases where surviving memory suppresses an answer the backbone would otherwise produce.
061   We then vary the deletion rule and its breadth to test how reliably different rules identify the memory
062   supporting a fact and what collateral damage broader deletion causes. We apply the same audit to both
063   systems, and add system-specific tests that examine the mechanisms exposed by each architecture.

068   2     R ELATED W ORK
069
070   Separable memory. Memory-based model editors store each edit outside the pretrained weights, and
071   the memory component holding a given fact is therefore known (Mitchell et al., 2022b; Hartvigsen
072
      et al., 2023; Wang et al., 2024). Limited Memory Language Models instead build their memory from
      a corpus, where the same fact can appear in many entries (Zhao et al., 2026; Feldman et al., 2026).
073
      NULLs builds on memorization sinks (Ghosal et al., 2025) and is evaluated on facts taken from the
074
      removed source itself (Ghosal et al., 2026), while we start from the fact to be deleted.
075
076   When retrieval hurts. Retrieved text can contradict what the model has learned in its weights
077   (Longpre et al., 2021; Xie et al., 2024), and irrelevant text can make a model worse than it would be
078
      without retrieval. Mallen et al. (2023) use a fixed retrieval corpus, whereas in our setting, deletion itself
      can lead the model to retrieve misleading text, which we measure as surviving-memory interference.
079
080   Probing and attacks. Linear probes test what can be decoded from a representation (Alain & Bengio,
081   2017; Hewitt & Liang, 2019), while adversarial passages can hijack retrieval (Zhong et al., 2023)
082   and, in RAG systems, induce attacker-chosen answers (Zou et al., 2025). We use both to test whether
083   a deleted answer remains internally encoded and whether one inserted entry can undo a deletion.
084   Auditing deletion. Raeesi & Roed (2026) audit deletion by comparing three memory conditions.
085   There, each memory entry is a subject–relation–object triple, and the canonical and alias-equivalent
086   entries for a fact can be enumerated and deleted. We adopt this three-condition design for Co-LMLM
087   and NULLs, whose memory units are free-text entries and training sources rather than triples. We
088   also add surviving-memory interference, deletion rules, and probing and re-insertion tests.

196   3.2   A PPLYING THE AUDIT TO C O -LMLM AND NULL S

198   We apply the same audit to two systems with different forms of separable memory: Co-LMLM (Feld-
199   man et al., 2026) and NULLs (Ghosal et al., 2026). The systems differ in what a memory unit is, in
200   how the model reads from an enabled memory M′ , and in the rules used to construct R(f ).
201   Co-LMLM. In Co-LMLM, the backbone is a language model with parameters θ, and the separable
202   memory is an external key–value store whose entries are the memory units: M = {(ki , vi )}N  i=1 .
203   Each key ki is an L2 -normalized hidden state emitted at a <FACT> token, and each value vi is the
204   associated text span. When the model emits <FACT>, its L2 -normalized hidden state q queries the
205   enabled memory M′ by cosine similarity,
206

209
      otherwise, and always when M′ = ∅, generation continues without retrieval.

248   Co-LMLM and NULLs differ in model size, training data, objective, and memory implementation.

253   Co-LMLM, we use the contents of the retrieval store to ask whether answers that occur more densely

316   4.2   W HAT SUPPORTS AN ANSWER AFTER DELETION ?
317
318   Our first experiment asks why a fact is still recited after deletion. For each system, we apply its
319   standard deletion rule and compare DEL-ON with DEL-OFF. If a fact is recited only under DEL-
320
      ON, it depends on memory that survived (SMS). If it is also recited under DEL-OFF, the backbone
      recites it without that memory. Table 1 reports these outcomes.
321
322   On T-REx, Co-LMLM recites 8.3% of facts under DEL-ON (PDR), but only 1.5% are recited
323   because of surviving memory (SMS). For NULLs, the corresponding rates are 80.7% and 8.1%.
      The same pattern appears on CounterFact. Therefore, most of the facts recited after deletion are


                                                          6
      Under review as a conference paper at ICLR 2027




324
      answerable by the backbone alone. Deleting more memory cannot remove them; whether they can be
325   deleted depends on how well training keeps them out of the backbone.
326
327   Deletion can also produce the opposite effect. Some facts are no longer recited under DEL-ON
328
      even though the backbone recites them under DEL-OFF. This surviving-memory interference
      (SMI) affects 18.8% of Co-LMLM facts on T-REx and 19.9% on CounterFact. NULLs also shows
329
      interference, at 8.4% on T-REx and 11.8% on CounterFact. The later system-specific analyses of
330
      NULLs suggest that many of these cases involve facts supported mainly by the shared backbone, while
331   changing the active source mask can still perturb the generated answer. In Co-LMLM, interference
332   can instead arise when the remaining external memory retrieves text that overrides an answer the
333   backbone recites without retrieval.
334
      For Co-LMLM, the spurious-deletion rate Φ is 20.5% on T-REx and 21.2% on CounterFact. For
335
      NULLs, Φ is 43.7% on T-REx and 35.8% on CounterFact. These rates show how often a before-
336
      and-after comparison can give a misleading picture of what deletion changed. For Co-LMLM, the
337   backbone still recites the fact, but retrieval after deletion hides it. For NULLs, this mostly reflects
338   deletion changing recitation about equally often in both directions (SMS ≈ SMI), not facts hidden
339   by the remaining memory (see Appendix F).
340
      The backbone recitation BBR is below the accuracy of both 360M reference models on every prompt
341
      set for Co-LMLM. Externalizing factual text therefore reduces how often the backbone recites these

      facts, but does not eliminate it.

344   Google-RE is an exception for Co-LMLM, where post-deletion and backbone recitation are both near
345   zero. The reference models, however, also answer only 3.0–5.8% of these facts, which suggests that
346
      the result reflects the difficulty of the prompt set more than the deletion. For NULLs, the Google-RE
      cohort (n = 35) is too small to draw conclusions.
347
348   For space, Appendix G reports PopQA and ZsRE. In Co-LMLM, surviving-memory support stays
349   below 1% on both. PopQA resembles T-REx and CounterFact, with interference far exceeding
350   support, while ZsRE resembles Google-RE, with all rates near zero. In NULLs, post-deletion and
351   backbone recitation remain close, though both cohorts are small (n = 22 and 79).

      4.3   D OES THE DELETION RULE MATTER ?
354
355
356
      The previous experiment uses one standard deletion rule for each system. We next ask whether
      the outcome changes when the same fact is mapped to different deletion sets. For Co-LMLM, we
357
      compare the oracle seed, geometric, provenance, <FACT-q>, and value rules described in Section 3.2,
358
      together with their unions. For NULLs, we compare the provenance, geometric, and value rules, and
359   the intersection of the latter two. Table 12 reports T-REx, Google-RE, and CounterFact.
360
361   For Co-LMLM, the value rule is much more effective at removing supporting memory because it
362
      explicitly uses the answer text when constructing the deletion set. The geometric, provenance, and
      <FACT-q> rules leave surviving-memory support (SMS) close to that of removing only the retrieved
363
      entry (30.0–36.3% on T-REx, 41.7–46.1% on CounterFact). However, every rule that includes the
364
      value rule reduces SMS to below 2%. The entries that support the answer therefore lie in other
365   source documents and below the geometric threshold. In short, explicitly using the answer text when
366   constructing the deletion set identifies supporting entries that the other rules miss.
367
368
      This reduction comes at a cost. Surviving-memory interference rises from 6.7 to 18.8% on T-REx
      and from 5.7 to 19.9% on CounterFact. A more complete deletion therefore makes more facts appear
369
      deleted, even though the backbone still recites them.
370
371   On Google-RE, the value rule likewise reduces surviving-memory support (SMS) from 14.1 to 0.2%,
372   but without raising interference. The backbone recites almost none of these facts, meaning there is
373   almost nothing for the remaining memory to hide.
374   For NULLs, the choice of rule barely changes surviving-memory support (SMS). This is consistent
375   with Appendix F, where SMS is unchanged when the next-closest source is replaced by an unre-
376   lated one: support after deletion is not tied to any particular source, leaving broader rules little to
377   remove. The value rule instead roughly halves surviving-memory interference (SMI) on T-REx and
      CounterFact. The Google-RE cohort (n = 35) is too small to draw conclusions.

      4.4     W HAT HAPPENS WHEN DELETION IS MADE BROADER ?
406
      We now hold the geometric rule (Rgeo ) fixed and vary its breadth. This asks whether disabling more
407
      memory units makes the target fact less likely to be recited, and whether doing so also affects nearby
408
      facts. For Co-LMLM, lowering the cosine threshold ρ broadens geometric deletion. For NULLs,
409   increasing k adds more neighboring sources to the deletion set. Since ρ and k control different
410   operations, we examine the trend within each system rather than compare their values directly.
411
412
      Although ρ and k are not comparable, the two systems respond to breadth in opposite ways. In
      Co-LMLM, broader deletion removes more targets at little cost to nearby facts, whereas in NULLs it
413
      costs nearby facts without removing more targets. This reflects where the audited facts mainly reside,
414
      in separable memory for Co-LMLM and in the shared backbone for NULLs.

417   4.5     ROBUSTNESS CHECKS
418
419   Surviving-memory support and interference both depend on how DEL-OFF is implemented, because
420   DEL-OFF determines whether the backbone recites the fact. We therefore test a second implementa-
421   tion of DEL-OFF for each system. For NULLs, we also vary the pre-deletion source check used to
422
      select facts for evaluation. Appendix C reports the full results.
423   For Co-LMLM, the two implementations of DEL-OFF give nearly the same result. Backbone recita-
424   tion differs by at most 1.0 percentage points across prompt sets, and surviving-memory interference
425   differs by at most 0.3 points. The interference we observe therefore does not depend on the particular
426   way retrieval is disabled.
427   NULLs is more sensitive to the choice of DEL-OFF, especially on the smallest evaluation sets, so we
428   treat its exact rates of surviving-memory support and interference more cautiously. We also tighten
429   the pre-deletion verification requirement so that the associated source must support the gold answer
430   by a larger margin. This removes many examples, but backbone recitation remains 69.7% on T-REx
431   and 44.3% on CounterFact at the strictest tested margin. Even among facts most clearly supported by
      their associated source, the backbone recites many of them without source-specific sink memory.

      4.6   S YSTEM - SPECIFIC ANALYSES
433
434   The experiments above use the same basic audit for both systems. We finish with additional tests that
435   use interfaces specific to each architecture.
436
      We first ask whether facts whose answers occur more densely near the query in the external store are
437
      also more likely to be recited by the backbone. Answer density is positively associated with backbone
438
      recitation, but less strongly for Co-LMLM than for the closed-book references. We next ask whether
439   answer information can be decoded from Co-LMLM’s query representation even when the backbone
440   does not recite the answer under DEL-OFF. A linear probe exceeds the strongest control by 5.6
441   points on T-REx, 10.0 on CounterFact, and 4.4 on Google-RE; the evidence is weak on PopQA and
442   absent on ZsRE. Finally, we test whether one surviving memory entry can reverse a deletion. A single
443   verbatim answer-bearing entry placed just outside the geometric deletion boundary restores recitation
444   for 37.9–83.0% of facts that were not recited after geometric deletion. Appendix E gives the full
445   analyses. For NULLs, we ask how much the source-specific sink associated with a fact contributes
446   to the model’s behavior. On four of the five prompt sets, the associated source mask makes the
447
      gold answer more likely than an unrelated source mask for only 50–52% of facts, and switching the
      associated source mask on or off changes fewer than 5% of generated answers in each direction. We
448
      then replace the next-closest source used after deletion with an unrelated source. The resulting rates
449
      of surviving-memory support and interference change little on the larger evaluation sets. Together,
450   these tests suggest that the evaluated facts are supported mainly by the shared backbone rather than by
451   one particular source-specific sink, which is consistent with the intended design of NULLs (Ghosal
452   et al., 2026). Appendix F gives the full analyses.

455   5     C ONCLUSION
456
457   We introduced an audit that evaluates each fact with memory intact, with the deletion set disabled, and
458   with separable memory disabled, and applied it to Co-LMLM and NULLs across five factual-recall
459
      benchmarks. In Co-LMLM, deletion appears more successful than it is. Up to 21.2% of facts that a
      before-and-after comparison counts as deleted are still recited by the backbone, hidden only by the
460
      remaining memory, and a single similar entry added outside the deletion set restores up to 83.0% of
461
      deleted facts. In NULLs, the shared backbone recites up to 81.1% of audited facts without any source
462   memory, consistent with its design for knowledge shared across sources. For such facts, deleting
463   more sources does not remove more targets but damages up to 13% of nearby facts.
464
465
      Our findings suggest what papers on separable memory should report to support a deletion claim.
      First, they should define how a requested fact is mapped to memory units, since the choice of rule
466
      largely determines how much supporting memory survives. Second, they should evaluate each fact
467
      under all three memory conditions and report the spurious-deletion rate Φ, since a before-and-after
468   comparison alone counts facts as deleted that the backbone still recites. Third, they should vary
469   deletion breadth, since broader deletion can remove more targets or only harm nearby facts, depending
470   on where facts reside. Finally, they should test how DEL-OFF is implemented, and, for external
471   memory, whether a single added entry can undo a deletion.
472
      The results also point to one possible change for each system. Co-LMLM inserts the nearest entry
473
      above its retrieval threshold without checking whether it concerns the queried fact. This may be part
474   of what allows the remaining memory to hide answers after deletion, and a single inserted entry to
475   disrupt it. A learned check on retrieved entries could make what the backbone still recites visible
476   rather than hidden. In NULLs, facts shared across articles appear to be held by the backbone because
477   no single source sink holds them. Assigning each document an entity- or cluster-level sink alongside
478   its article sink might give such facts a unit that source deletion can remove.
479
      Limitations. Recitation is measured with greedy decoding and answer matching, and backbone
480   recitation is therefore a lower bound on what the backbone retains, as the representation probe
481   indicates. We audit one model size per system and a fixed set of deletion rules, and other rules
482   may remove supporting memory with less interference. For NULLs, we use standard factual-recall
483   benchmarks rather than facts drawn from its training articles, which yields small audited cohorts
484   on several of the benchmarks. A matched baseline for each system would allow comparing how
485   much Co-LMLM and NULLs each reduce backbone recitation relative to a model without separable
      memory.

       E.3    A DVERSARIAL RE - INSERTION
996
997    A geometric deletion can stop the model from reciting a fact without showing that the fact is robustly
998    removed, since an answer-bearing entry may lie just outside the deletion set and still be retrieved. We
999    test this under a database-administrator threat model, where the adversary knows the deletion radius
1000   and can insert a single entry.
1001   For a target fact f , we attack the geometric deletion set Rgeo
                                                                   ρ (f ) at ρ = 0.85. The adversary inserts
1002   an entry (ka , va ) whose key lies just outside the boundary:
1003                                                √︁
1004                                   ka = γ q̂f + 1 − γ 2 u,       γ = ρ − ε,
1005
       where u is a random unit vector orthogonal to q̂f . Then ⟨q̂f , ka ⟩ = γ < ρ, so the entry survives the
1006
       deletion while remaining close to the query. The value va either states af verbatim or uses one of
1007   three templates designed to evade match: hyphenated (each word split by a hyphen), letter-spaced
1008   (the answer spelled letter by letter), or prefix-cue (the first and last characters of the answer and its
